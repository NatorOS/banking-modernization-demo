# AWS consumption

This page covers which services the application uses, what drives their usage, what was
measured, and what is only estimated. It makes no pricing or Marketplace claims; see the AWS
pricing pages for current rates.

## Services and usage drivers

| Service | Driver | Notes |
| --- | --- | --- |
| API Gateway HTTP API | One request per API call (dashboard click, CLI step, webhook delivery) | IAM auth; stage throttling (rate 10 req/s, burst 20) bounds runaway usage. |
| Lambda (python3.13, arm64, 256 MB, 15 s timeout) | One invocation per API request; duration scales with the DynamoDB round trips per request | No provisioned concurrency. |
| DynamoDB (foundation table, on-demand) | Strongly consistent `GetItem`/`Query` reads; `TransactWriteItems` for every state change; `BatchWriteItem` deletes on reset | Transactional writes consume more write capacity per item than standard writes (see the DynamoDB documentation on transactions and capacity). |
| Secrets Manager | One stored secret (simulator HMAC key); one `GetSecretValue` per Lambda cold start | Charged per secret and per API call. |
| CloudWatch Logs | One structured JSON line per Lambda request plus one API Gateway access log line | 7-day retention; no bodies or headers are logged. |
| S3 (foundation artifacts bucket) | One Lambda zip per deploy (`app/lambda-<sha>.zip`, about 50 KB) | The foundation lifecycle rule expires objects after 14 days. |

## Measured (local, in-process)

These numbers come from running `modern.demo run` once (the full nine-step scripted demo)
against `DynamoStore` backed by moto, counting client calls. They measure **request volume**
generated by the code. They do **not** measure AWS-billed consumption.

| Metric | Value |
| --- | --- |
| HTTP API requests (equals Lambda invocations in AWS mode) | 17 |
| DynamoDB `GetItem` (strongly consistent) | 83 |
| DynamoDB `Query` (strongly consistent) | 14 |
| DynamoDB `TransactWriteItems` calls / items written | 27 / 78 |
| Items in the namespace partition after the demo | 39 |

The dashboard state view also reports the running process's own counters (`process_usage`).

## Estimates (not measured)

- **Per payment lifecycle** (submit → settle → return): about 3 HTTP requests and about 3–4
  transactions writing roughly 12–14 items. This is derived from the transaction shapes in
  `modern/service.py`. Per-item write units depend on item size; payment items grow with their
  `history` list.
- **Idle cost drivers:** the Secrets Manager secret and any stored log and table data. There is
  no idle compute.
- **AWS-measured consumption** is pending deployment. After deploying, read it from CloudWatch
  metrics (`AWS/ApiGateway Count`, `AWS/Lambda Invocations/Duration`,
  `AWS/DynamoDB ConsumedRead/WriteCapacityUnits`) and Cost Explorer filtered by the
  `Project=banking-modernization-demo` tag.
